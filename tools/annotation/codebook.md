# PinTrace 标注编码手册

版本 v1.0（2026-11-08）· 适用于标注包 `annotation-packet-v1`

本手册说明每个标签的含义和判定规则。正式标注前请完整读一遍，标注时可随时查阅。

---

## 1 你要做什么

GitHub Actions 的工作流文件（`.github/workflows/*.yml`）用 `uses:` 引用别人写好的 Action，例如：

```yaml
steps:
  - name: Checkout
    uses: actions/checkout@v4          # 引用 actions/checkout 的 v4
  - uses: actions/setup-node@1a4442cacd436585916779262731d5b162bc6ec7  # v3.8.1
```

`@` 后面的部分叫**引用值（ref）**，它决定实际运行哪一份代码。行尾 `#` 后面的是**注释**。

标注包里有两类题目：

| 题型 | 你看到的材料 | 你要回答的问题 |
|---|---|---|
| **引用分类** | 一条 `uses:` 引用，以及它所在文件的上下文 | 这条引用属于哪一类？ |
| **变化判断** | 一次提交前后的若干条引用、文件上下文和这次提交的改动 | 与变更前相比，这些引用发生了什么？ |

每题选**一个**标签，再选**把握程度**（高/中/低），需要时写**备注**。

---

## 2 基本原则

1. **只看材料本身。** 依据题目给出的文件内容、改动和提交链接判断。不要猜测作者的动机，也不要查找本研究的论文或代码。
2. **按实际发生的情况标。** 没有"标准答案"，也没有"希望你选的答案"。
3. **拿不准就选 `unknown`，并在备注写原因。** 这比勉强给出一个答案更有价值。
4. **独立完成。** 正式标注期间不要和另一位标注者交流具体题目。规则问题请发给组织者，答复会以 FAQ 形式同时发给两人。

---

## 3 关键概念

**完整 SHA**：恰好 **40 位**十六进制字符（0–9、a–f，大小写均可），例如 `1a4442cacd436585916779262731d5b162bc6ec7`。

- 39 位、41 位或 7 位的短哈希（如 `1a4442c`）**不是**完整 SHA。
- 只看 `@` 后面的值，**不看注释**。注释里写着 `v3.8.1`，不影响它是否为完整 SHA。

**可变引用**：除完整 SHA 以外的引用值，例如标签 `v4`、`v4.1.2`、`2.0`，分支 `main`、`master`、`release/v1`，以及短哈希。这类值指向的代码可能被改动，所以叫"可变"。

**Action 身份**：`@` 前面的 `owner/repo`，加上可能有的子路径，例如 `github/codeql-action/init`。`owner/repo` 不区分大小写。

**同一条引用**：变更前后**同一个步骤**（step）里的 `uses:`。下列情况仍算同一条引用：

- 只是行号变了（上面插入或删除了别的行）；
- 文件改名了，内容对应；
- job 或 step 改了名，但能看出是同一个步骤；
- 步骤的位置在文件里挪动了。

## 4 题型一：引用分类

问题：**这条 uses 引用属于哪一类？**

| 标签 | 含义 | 例子 |
|---|---|---|
| `pinned` | 外部 Action，引用值是**完整 40 位 SHA** | `actions/checkout@8e5e7e5ab8b370d6c329ec480221332ada57f0ab` |
| `mutable` | 外部 Action，引用值**不是**完整 SHA | `actions/checkout@v4`、`foo/bar@main`、`foo/bar@1a4442c` |
| `not_direct` | 不是直接引用外部 Action 的形式 | `./.github/actions/build`（本地）、`docker://alpine:3.19`、job 级别引用可复用工作流 `org/repo/.github/workflows/ci.yml@v1`、含表达式的 `${{ matrix.action }}` |
| `unresolvable` | 根据材料无法判断，或写法残缺 | 没有 `@`；值被截断；该行看不到 `uses:` |

**判定顺序**

1. 以 `./` 开头、以 `docker://` 开头、含 `${{`，或是 job 级别指向 `.github/workflows/*.yml` 的，选 `not_direct`。
2. 形如 `owner/repo[/路径]@值` 的：`值`恰好是 40 位十六进制，选 `pinned`；否则选 `mutable`。
3. 以上都套不上，选 `unresolvable`。

> 注意：注释不影响分类。`foo/bar@v4  # 8e5e7e5…` 是 `mutable`。

## 5 题型二：变化判断

问题：**与变更前相比，这些引用发生了什么？**

页面左侧"变更前"和右侧"变更后"列出了这道题**关注的引用**，下方是这次提交对相关文件的**改动**（红色为删除行，绿色为新增行）。一侧可能为空，例如新增或删除时。

### 5.1 标签

| 标签 | 含义 | 例子（变更前 → 变更后） |
|---|---|---|
| `pin` | 同一条引用，同一个 Action，可变值 → 完整 SHA | `actions/checkout@v4` → `actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683` |
| `unpin` | 同一条引用，同一个 Action，完整 SHA → 可变值 | `foo/bar@8e5e…f0ab` → `foo/bar@v2` |
| `sha_change` | 同一条引用，同一个 Action，完整 SHA → **另一个**完整 SHA | `foo/bar@8e5e…f0ab` → `foo/bar@11bd…f683` |
| `tag_change` | 同一条引用，同一个 Action，可变值 → **另一个**可变值 | `actions/setup-node@v3` → `actions/setup-node@v4`；`foo/bar@main` → `foo/bar@v1.2` |
| `replace` | 同一个步骤，改用了**另一个** Action（`owner/repo` 或子路径不同） | `tj-actions/changed-files@v45` → `dorny/paths-filter@v3` |
| `remove` | 变更前有这条引用，变更后**没有了**（步骤、job 或文件被删，或该行被注释掉） | 右侧为空，改动中该行被删 |
| `entry` | 变更前**没有**，变更后**新出现**（新步骤、新 job、新文件、复制已有步骤、删除后重新加回） | 左侧为空，改动中该行为新增 |
| `no_change` | 引用还在，`uses:` 的值**没有变** | 只有行号移动、文件或 job 改名、注释改动、周围其他行改动 |
| `mixed` | 题目里有**多条**引用，且它们发生的变化**不同** | 一条 `pin`，另一条 `remove` |
| `unknown` | 根据材料**无法判断** | 见 5.3 |

### 5.2 判定步骤

1. **配对**：对左侧每条引用，在右侧找"同一条引用"（见第 3 节）。可以对照下方改动和文件上下文：步骤名、`with:` 参数、所在 job 和前后步骤。
2. **逐条判断**：
    - 有对应，Action 相同：比较引用值 → `pin` / `unpin` / `sha_change` / `tag_change` / `no_change`。
    - 有对应，Action 不同 → `replace`。
    - 左侧有、右侧找不到对应 → `remove`。
    - 右侧有、左侧找不到对应 → `entry`。
3. **汇总**：
    - 所有引用结果相同，就选这个标签。例如三条引用都改成了 SHA，选 `pin`。
    - 结果不同，选 `mixed`，并在备注写明各自是什么。
    - 无法确定配对，而不同的配对方式会得出**不同**的答案，选 `unknown`。如果每种配对方式答案都一样，就选那个答案。

### 5.3 什么时候选 `unknown`

- 两侧各有几条相同 Action 的引用，看不出谁对应谁，而不同的对应方式会导致不同的结论；
- 文件内容显示不全，改动被截断，点开 GitHub 链接也无法确认；
- 材料自相矛盾。

选 `unknown` 时，请在备注里写一句原因，例如"两个 checkout 步骤无法对应"。

### 5.4 容易混淆的情况

| 情况 | 应选 |
|---|---|
| 只改了 SHA 的大小写（`ABC…` → `abc…`） | `no_change` |
| SHA 没变，只是注释从 `# v4.1.0` 改成 `# v4.2.0` | `no_change` |
| SHA 变了，注释也跟着改了 | `sha_change` |
| `v4` → `v4` 对应提交的完整 SHA | `pin` |
| 短哈希 `1a4442c` → 完整 40 位 SHA | `pin`（短哈希属于可变值） |
| 完整 SHA → 短哈希 | `unpin` |
| `owner/repo` 和引用值都变了 | `replace` |
| 同一个 Action 只是 `owner` 大小写不同（`Actions/Checkout` → `actions/checkout`） | 看引用值：值没变就选 `no_change` |
| 步骤被整段注释掉（行首加了 `#`） | `remove` |
| 文件被整体删除 | `remove` |
| 文件改名，内容不变 | `no_change` |
| 新建了一个工作流文件 | `entry` |
| 把已有步骤复制了一份 | `entry`（关注的是新出现的那份） |
| job 改了名，步骤和引用值都没变 | `no_change` |

## 6 把握程度

| 选项 | 何时选 |
|---|---|
| 高 | 证据清楚，换一个认真的人来看也会得出同样结论 |
| 中 | 基本确定，但需要一些推断，例如靠上下文判断配对 |
| 低 | 有较大不确定性，这时请在备注写明原因 |

---

## 7 备注怎么写

以下情况请写备注：选 `unknown` 或 `mixed`、把握程度为低、你认为题目材料有问题。一句话即可，例如：

- `mixed：checkout 改成 SHA，cache 被删除`
- `unknown：两个 setup-node 步骤都改了，看不出对应关系`
- `改动被截断，打开 GitHub 链接确认后判断`
